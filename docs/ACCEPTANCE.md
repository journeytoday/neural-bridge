# Bounded v0.1 software POC acceptance record

10 September 2026. This records engineering demonstration evidence, not clinical readiness or production certification. The source PRD remains confidential and is not included in the public repository.

## Completed demonstration paths

- Compose, select, confirm, edit and explicitly speak a message; ordinary text remains available independently of prediction.
- Process synthetic quality-qualified observations, propose bounded target/timing/confirmation changes, require approval, refuse, expire proposals, undo or enter recovery, preserving the draft.
- Coordinate synthetic EEG/gaze candidates with disagreement, timestamp, artifact and quality guards. Unknown remains unknown.
- Run labeled posture/geometry loss with constant underlying capability, separate gaze/blink/pupil observability, working non-ocular fallback, an HTTP repositioning-help request and separate channel revalidation before return. Generic recovery cannot replace ocular checks.
- Decode actual WebM frames for synthetic eye geometry and compare long closure, short natural-blink control, no-intent and lost-visibility fixtures. This is not a human-face detector or calibrated intent decoder.
- Gate simulated voice transcripts on recent reliability, and retain explicitly approved corrected text as an alternative.
- Generate editable suggestions with a small actual statistical language model; support long-form composition, ordinary selectable device voice assets and default fallback. No voice cloning is claimed.
- Persist versioned profiles, export/import, demonstrate an independent second browser host with local interaction checks, and test conflict/offline/revocation handling.
- Route help and MI candidates through real loopback HTTP sandbox endpoints with deduplication, acknowledgements and timeouts. No real emergency recipient is contacted.
- Display a fictional medication timeline with separate acknowledgement, reported administration and unknown state. No treatment decision or dose alteration exists.
- Install test-author interaction rules with scope, revision, integrity and expiry checks; enforce bounds on subsequent changes and undo; explicitly review expired test rules.
- Retain bounded text-free event summaries, explicit feedback/refusals and approved personal vocabulary locally. Historical sensor data never becomes current reliability.

## Verification and artifacts

33 Node tests pass. Browser checks cover the core adaptation/undo loop, WebM decoding, HTTP request completion, independent host validation, vocabulary, voice correction, order expiry, posture recovery and keyboard-focus dwell. A 390-pixel mobile layout was visually inspected. There is no claim of exhaustive assistive-technology testing or auditory intelligibility validation.

The walkthrough is a 42-second captioned sequence of captured UI states, not a continuous live screen recording. It illustrates the actual demonstrator; the keyboard timer's duplicate-status issue visible in an early captured state was subsequently corrected and retested. The recording contains only fictional demonstration text.

Architecture and capability boundaries are in README.md; SDK contracts are in SDK.md. Reproduce the comparison with `node scripts/evaluate.js`. Per-episode outputs and mixed comparator results are retained in evaluation/. No superiority claim is made.

## Deliberate limitations and next funding milestone

The POC uses deterministic fixtures, a small statistical language model, ordinary device voices, a local single-user service, and a test checksum rather than clinical signatures. Live EEG/ASR, human blink calibration, voice cloning, secure multi-user cloud deployment, real care equipment, validated PK and clinical studies are later milestones. Broader M01–M12 scope is retained in the capability matrix.

Next milestone: select and integrate one supported real access route, verify the supported hardware/setup, commission specialist accessibility and safety review, and agree the supervised evaluation protocol. Cost assumptions: local demo runtime has no paid API requirement; engineering labor, hardware, professional review, study delivery, hosting and contingency need actual capacity and supplier quotations. The POC does not invent a funding amount, recruitment commitments, medical effectiveness or reimbursement eligibility.
